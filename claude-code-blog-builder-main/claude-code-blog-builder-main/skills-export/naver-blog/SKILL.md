# 네이버 블로그 작성·수정·발행 스킬

이 파일 하나로 동작한다. 외부 스크립트나 프로젝트 파일이 없어도 된다.
도구가 있으면 쓰고(브라우저 자동화, 웹 검색, 파일 쓰기), 없으면 결과물을 텍스트로 사용자에게 준다.

---

## 0. 시작할 때 확인할 것

사용자 요청에서 아래를 확인한다. 빠진 항목만 한 번에 묻는다. 추측 가능한 것은 묻지 않는다.

| 항목 | 예시 | 기본값 |
|---|---|---|
| 작업 종류 | 새 글 작성 / 기존 글 수정 / 발행만 / 문체 분석만 | 새 글 작성 |
| 글 유형 | 리뷰, 후기, 일기, 여행기, 맛집, 정보성, 브랜드 홍보 | 키워드로 추정 |
| 메인 키워드 | "제주 애월 카페", "다이슨 에어랩 후기" | 필수 |
| 블로그 주소 | `https://blog.naver.com/<아이디>` | 문체 분석 시 필수 |
| 사용자 자료 | 사진, 메모, 방문 날짜, 가격, 영수증, 느낀 점 | 있으면 반드시 사용 |
| 협찬 여부 | 내돈내산 / 협찬 / 광고 | 묻는다 (리뷰·후기일 때) |
| 발행 방식 | 바로 발행 / 예약 발행 / 임시저장만 / 원고만 | 원고만 |

**사실 원칙**: 사용자가 준 자료와 검증된 공개 정보만 쓴다. 가격, 수치, 영업시간, 방문 경험을 지어내지 않는다. 모르는 값은 `[확인 필요: 가격]`처럼 표시하고 사용자에게 넘긴다.

## 1. 로그인

네이버는 공식 글쓰기 API를 제공하지 않는다. 작성·발행은 브라우저에서 스마트에디터 ONE으로 한다.

1. 브라우저 자동화 도구가 있으면 새 탭으로 `https://nid.naver.com/nidlogin.login`을 연다.
2. **아이디와 비밀번호는 사용자가 직접 입력한다.** 에이전트는 비밀번호를 묻지 않고, 받지 않고, 저장하지 않고, 입력하지 않는다. 캡차·2단계 인증·기기 확인도 사용자가 처리한다.
3. 사용자가 "로그인 완료"라고 하면 `https://blog.naver.com/<아이디>`로 가서 로그인 상태를 확인한다. 상단에 "글쓰기" 버튼이 보이면 로그인된 상태다.
4. 이미 로그인된 브라우저 세션이 있으면 1~2단계는 건너뛴다.
5. 브라우저 도구가 없으면 로그인 단계는 건너뛴다. 원고만 만들고 발행은 사용자에게 안내한다(7장).

로그인이 2~3번 실패하거나 보안 경고가 뜨면 멈추고 사용자에게 상황을 설명한다. 우회하지 않는다.

## 2. 기존 글 문체 분석

새 글이 블로그 주인의 말투처럼 읽히게 하는 단계다. 블로그 주소가 있으면 반드시 한다.

### 2-1. 샘플 수집

- 같은 블로그에서 최근 글 5~10편을 고른다. 쓰려는 글과 같은 유형(여행기면 여행기)을 우선한다.
- 글 목록: `https://blog.naver.com/PostList.naver?blogId=<아이디>`
- 본문은 모바일 주소가 읽기 쉽다: `https://m.blog.naver.com/<아이디>/<글번호>`
- 본문 텍스트만 모은다. 목표 분량은 3만 자 이상이다. 부족하면 정확도가 낮다고 사용자에게 알린다.
- 수집할 수 없으면 사용자에게 글 3~5편의 본문을 붙여넣어 달라고 한다.
- 남의 블로그를 분석할 때는 문체만 참고한다. 문장을 복사하지 않는다.

### 2-2. 분석 항목

아래 항목을 표로 정리해서 사용자에게 보여주고 확인을 받는다.

| 항목 | 볼 것 |
|---|---|
| 종결 어미 | ~다 / ~요 / ~습니다 / ~ㅎㅎ / 반말 섞임 비율 |
| 문장 길이 | 평균 길이, 한 줄 단문 사용 빈도 |
| 문단 길이 | 1~2줄 끊기(모바일형)인지, 긴 문단인지 |
| 호칭·인칭 | "저", "나", "제가", 독자를 부르는 말("여러분", "이웃님") |
| 습관어·연결어 | "정확히는", "다만", "근데", "암튼" 같은 반복 표현 |
| 감정 표현 | 이모티콘, ㅋㅋ/ㅎㅎ, 느낌표 빈도 |
| 소제목 스타일 | 번호형, 질문형, 숫자+기간형("3일째, 드디어") |
| 도입·마무리 | 인사로 시작하는지, 마무리 인사·이웃 추가 유도 문구 |
| 사진 배치 | 사진 사이 문장 수, 사진 설명 캡션 사용 여부 |
| 정보 표기 | 주소·가격·영업시간을 표로 쓰는지, 글로 쓰는지 |

### 2-3. 결과물: 톤 카드

분석이 끝나면 아래 형식의 "톤 카드"를 만든다. 이후 모든 작성·수정은 이 카드를 따른다.

```markdown
## 톤 카드: <블로그 이름>
- 기본 어미: ~요체 70%, ~다체 30%
- 문단: 1~2문장마다 줄바꿈
- 시그니처 표현 5개: "...", "...", "...", "...", "..."
- 감정 표현: ㅎㅎ 글당 2~3회, 이모티콘 거의 없음
- 소제목: "📍 장소명" 형식
- 도입 습관: 날씨/계기 한 줄로 시작
- 마무리 습관: "오늘 포스팅은 여기까지!" + 다음 글 예고
- 피할 것: 이 블로그가 안 쓰는 말투 (예: 딱딱한 ~습니다체)
```

새 글에는 시그니처 표현을 **2개 이상** 자연스럽게 넣는다. 억지로 끼우지 않는다.

블로그 주소가 없으면 글 유형별 기본 톤(4장)을 쓴다.

## 3. 키워드 리서치

웹 검색 도구로 네이버 검색 결과를 확인한다. 네이버 검색 API 키(`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`)가 있으면 블로그 검색 API(`https://openapi.naver.com/v1/search/blog.json?query=<키워드>`)의 `total` 값을 쓴다.

### 3-1. 경쟁도

| 블로그 문서 수 | 판정 | 전략 |
|---|---|---|
| 10만 이상 | 높음 | 롱테일 키워드로 공략 ("애월 카페" → "애월 오션뷰 카페 주차") |
| 3만~10만 | 보통 | 메인 키워드 + 다른 각도 |
| 3만 미만 | 낮음 | 메인 키워드 정면 공략 |

### 3-2. 할 일

- 상위 글 5~10개의 제목을 보고 반복되는 연관 키워드 10~15개를 뽑는다.
- 롱테일 키워드 5~8개를 제안한다. 변형 예: "<키워드> 후기", "<키워드> 가격", "<키워드> 추천", "<키워드> 주차", "<키워드> 웨이팅".
- 독자 단계를 정한다: 무관심 / 관심 / 비교 / 결정. 단계에 따라 글의 각도가 달라진다.
- 상위 글들이 다루지 않는 빈틈(가격 비교, 실패담, 실제 소요 시간 등)을 1개 이상 찾는다.

### 3-3. 리서치 브리프

```markdown
# 리서치 브리프: <키워드>
- 경쟁도: N건 / 높음·보통·낮음
- 독자 단계: 비교 (근거: 상위 글 대부분이 "vs", "차이" 포함)
- 메인 키워드: ...
- 서브 키워드: ...
- 롱테일 후보: ...
- 상위 글 제목 5개: ...
- 차별화 각도: ...
- 피할 제목 유형: ...
```

## 4. 글 유형별 구조

모든 유형에 공통 규칙(5장)을 적용한다. 아래는 유형별 뼈대와 기본 톤이다.

### 리뷰 (제품·서비스)
- 기본 톤: ~요체, 솔직함 강조
- 구조: 구매 계기 → 첫인상/스펙 표 → 실제 사용 경험(기간 명시) → 장점 → 아쉬운 점(반드시 1개 이상) → 이런 분께 추천/비추천 → 총평
- 필수: 가격·구매처·사용 기간. 협찬이면 **글 맨 앞**에 "본 포스팅은 OO로부터 제품을 제공받아 작성했습니다" 표기.

### 후기 (방문·체험·수강)
- 기본 톤: ~요체, 경험 중심
- 구조: 방문 계기 → 기본 정보 표(위치·시간·가격·주차) → 과정 순서대로 → 좋았던 점 → 아쉬운 점 → 재방문 의사 → 팁
- 필수: 방문 날짜. 정보는 "방문 당시 기준"이라고 적는다.

### 일기 (일상)
- 기본 톤: 블로그 주인의 평소 말투. 반말·~다체 허용
- 구조: 오늘의 한 줄 → 시간 순서 장면 2~4개 → 느낀 점 → 짧은 마무리
- 키워드·SEO 규칙은 느슨하게 적용한다. 글자 수 하한 없음. 표 불필요.

### 여행기
- 기본 톤: ~요체, 현장감
- 구조: 여행 개요 표(기간·동행·교통·총경비) → 일차별/장소별 소제목 → 장소마다 [사진 → 감상 → 정보 한 줄] → 경비 정리 표 → 다음 여행자 팁
- 필수: 장소명, 이동 수단, 소요 시간. 여러 장소면 "📍 장소명" 같은 일관된 소제목.

### 맛집
- 기본 톤: ~요체
- 구조: 한 줄 총평 → 매장 정보 표(주소·영업시간·브레이크타임·주차·웨이팅) → 메뉴판·주문 메뉴와 가격 → 메뉴별 맛 묘사 → 분위기·서비스 → 재방문 의사
- 필수: 가격, 웨이팅 시간. 맛 묘사는 "맛있다" 대신 식감·온도·간·양으로 쓴다.

### 정보성 (방법·비교·가이드)
- 기본 톤: ~요체 또는 ~습니다체 (톤 카드 우선)
- 구조: 도입 4줄 공식 → 결론 먼저 → 단계별 설명 또는 비교 표 → 주의사항 → 요약
- 필수: 표 1개 이상, 출처가 있는 정보만.

### 브랜드·업체 홍보
- 기본 톤: 업체 톤 카드
- 구조: A.E.A — 권위(Authority: 왜 우리가 말할 자격이 있나) → 근거(Evidence: 사례·수치·과정) → 행동(Action: 강요 없는 다음 단계 제안)
- 필수: 업체가 준 수치만 사용. 광고 표기. 아래 6장의 업종별 금지 표현 검사.

### 도입부 4줄 공식 (정보성·홍보에 사용, 리뷰·후기는 선택)
1. 문제: 독자가 겪는 상황
2. 손실: 그대로 두면 생기는 손해
3. 자격: 내가 이 글을 쓸 수 있는 이유(경험·기간·횟수)
4. 약속: 끝까지 읽으면 얻는 것

### 패턴 선택 (정보성·홍보)
키워드 성격에 맞는 패턴 1~2개를 고른다. 같은 블로그의 최근 글과 겹치지 않게 한다.
- 가격·견적 키워드 → 비용 분해 패턴 (항목별 비용 표 + 왜 그 가격인지)
- "추천·업체 선택" → 실패 사례 패턴 또는 "왜?" 질문 패턴
- 신제품·트렌드 → 비교·벤치마크 패턴
- 절차·방법 → 프로세스 공개 패턴 (단계 번호 + 단계별 소요 시간)
- 고민 해결 → Before/After 케이스 패턴

## 5. 작성 공통 규칙

### 5-1. 분량·키워드
| 항목 | 기준 (일기 제외) |
|---|---|
| 본문 길이 | 공백 포함 1,500~3,000자 |
| 메인 키워드 | 본문에 5~12회, 자연스럽게. 억지 반복 금지 |
| 제목 | 메인 키워드를 앞쪽에. 25~35자. 낚시성 금지 |
| 소제목 | 3~6개. 일부에 서브 키워드 |
| 표 | 1개 이상 (정보 요약) |
| 이미지 자리 | `[사진: 설명]` 마커 4개 이상. 실제 사진이면 사용자 사진 번호 매칭 |
| 외부 링크 | 0개 (네이버 저품질 위험). 필요하면 "OO 공식 홈페이지 참고"처럼 글로만 |
| 태그 | 10개 (메인 1 + 서브 4 + 롱테일 5) |

### 5-2. 문체 변주
- 같은 종결 어미를 3문장 연속 쓰지 않는다.
- 긴 문장 사이에 한 줄 단문을 넣어 리듬을 만든다.
- 접속사("또한", "그리고", "더불어", "아울러", "뿐만 아니라")는 전체 문장의 5% 이하.
- 모바일 기준 1~3문장마다 줄바꿈한다(톤 카드가 다르면 톤 카드 우선).
- 핵심 문장은 **볼드**로 1~2곳만.

### 5-3. 금지 표현
| 분류 | 단어 | 이유 |
|---|---|---|
| 최상급 | 최고, 최저, 최상, 무조건, 100%, 절대, 완벽, 유일, 독보적 | 저품질 위험 + 과장 광고 |
| AI 말투 | 다양한, 효과적인, 중요한, 핵심적인, 전반적인, 궁극적인, 혁신적인, 최적의 | AI 글 티가 남. 최소화 |
| 과장 수치 | "300% 증가", "매출 10배" 같은 검증 불가 수치 | 허위 의심 |
| 단정·보장 | 확실한 효과, 부작용 없음, 원금 보장, 업계 1위, 국내 최초 | 표시광고법 |
| 교육 | 취업 보장, 합격 보장, 환급 보장, 100% 수강 만족 | 표시광고법 |
| 협찬 숨김 | 협찬인데 "내돈내산" 표기, 광고 표기 누락 | 공정위 추천·보증 심사지침 |

### 5-4. 마무리
- 강요 없는 마무리. 예: "비슷한 고민 있으시면 다른 글도 한번 둘러봐 주세요."
- 톤 카드의 마무리 습관을 따른다.

## 6. 품질 검사

글을 다 쓰면 아래를 직접 검사한다. 하나라도 FAIL이면 고치고 다시 검사한다.

### 6-1. 자동 검사 7항목
| # | 항목 | 통과 기준 |
|---|---|---|
| 1 | 키워드 빈도 | 메인 키워드 5~12회 |
| 2 | 글자 수 | 1,500자 이상 (일기 제외) |
| 3 | 어미 반복 | 같은 어미 3연속 없음 |
| 4 | 이미지 마커 | 4개 이상 |
| 5 | 외부 링크 | 0개 |
| 6 | 금지 표현 | 0개 (5-3 표) |
| 7 | 접속사 비율 | 5% 이하 |

### 6-2. 사람 눈 검사 10항목 (각 1~10점)
1. 수치·사실 정확성: 사용자 자료나 검증된 정보에 있는 숫자만 썼나
2. 톤 일치도: 톤 카드의 시그니처 표현이 2개 이상 자연스럽게 들어갔나
3. 도입부: 첫 3줄 안에 읽을 이유가 있나
4. 구조: 유형별 뼈대(4장)를 따랐나
5. 패턴 정합성: 고른 패턴대로 썼나
6. 문체 변주: 어미·문장 길이·연결어 반복이 없나
7. 구어체 자연스러움: 블로그 주인의 말투처럼 읽히나
8. 표·볼드: 핵심이 표·볼드로 정리됐나
9. 마무리: 강요 없이 자연스러운가
10. 금지 표현·외부 링크 0

총점 판정:
- 85점 이상: 발행 가능
- 70~84점: 지적 사항 고친 뒤 재검사
- 70점 미만: 다시 쓴다

점수는 엄격하게 준다. 애매하면 감점한다.

### 6-3. 의료·뷰티 글 추가 검사
키워드에 병원, 의원, 치과, 한의원, 피부과, 성형, 시술, 필러, 보톡스, 리프팅, 레이저, 임플란트, 교정, 다이어트, 탈모가 있으면 검사한다.

| 위반 유형 | 금지 예 |
|---|---|
| 과장·단정 | 100% 효과, 확실한 결과, 부작용 없음, 안전 보장, 기적의 |
| 비교·우위 | 다른 병원보다 ~배, 타사 대비 우월, 출처 없는 1위·TOP |
| 환자 유인 (의료법 제27조) | 할인·이벤트 강조, 저렴한 가격, 선착순, 한정 특가 |
| 치료 효과 단정 | 낫는다, 완치, 근본 치료, 이 시술만 받으면 |
| 자격 과장 | 근거 없는 명의, 권위자 |

위반을 찾으면 `| 위치 | 표현 | 위반 유형 | 대체 문구 |` 표로 보고하고 고친다. 의료 시술 후기는 "개인차가 있을 수 있습니다"를 넣는다.

### 6-4. 중복 검사
- 같은 블로그의 기존 글과 문장이 겹치지 않게 한다. 기존 글 본문이 있으면 6어절 단위로 겹치는 구간을 찾는다. 겹침이 25%를 넘으면 다시 쓴다.
- 다른 사람 글의 문장을 가져오지 않는다.

## 7. 이미지

- 사용자 실제 사진이 최우선이다. 리뷰·후기·여행기·맛집은 실제 사진 없이 발행하지 않는다.
- 사진 순서는 본문 `[사진: 설명]` 마커 순서와 맞춘다. 사진마다 1~2줄 설명을 붙인다.
- 정보성·홍보 글은 보조 이미지를 만들 수 있다: 썸네일(16:9, 메인 키워드 텍스트), 인포그래픽(2:3, 핵심 포인트), 인용 카드(1:1, 핵심 문장), 과정 도식(4:3, 단계).
- 이미지 생성 도구가 없으면 위 4종의 문구와 구성안만 텍스트로 준다.
- 같은 이미지를 여러 글에 재사용하지 않는다(유사 문서 판정 위험).
- 첫 번째 사진 또는 썸네일을 대표 이미지로 지정한다.

## 8. 결과물 형식

글을 쓰면 아래를 만든다. 파일 쓰기가 가능하면 `<날짜>_<키워드>/` 폴더에 저장하고, 아니면 채팅으로 준다.

1. `post.md`: 본문 마크다운
2. `post.html`: 스마트에디터 붙여넣기용 HTML. 허용 태그는 `h2`, `h3`, `p`, `strong`, `table`, `ul`, `li`만 쓰고, 인라인 스타일은 쓰지 않는다.
3. `metadata.json`: 아래 형식

```json
{
  "title": "제목",
  "type": "리뷰|후기|일기|여행기|맛집|정보성|홍보",
  "keyword": "메인 키워드",
  "sub_keywords": [],
  "tags": ["10개"],
  "category": "블로그 카테고리",
  "pattern": "고른 패턴",
  "tone_card_applied": true,
  "quality": { "auto": "7/7 PASS", "score": 0 },
  "needs_check": ["[확인 필요] 항목 목록"]
}
```

4. `guide.md`: 사진 넣을 위치, 사람이 확인할 사실 목록, 발행 체크리스트

## 9. 기존 글 수정

1. 수정할 글 URL을 받는다. 본문은 `https://m.blog.naver.com/<아이디>/<글번호>`에서 읽는다.
2. 수정 목적을 확인한다: 정보 갱신(가격·영업시간) / 키워드 보강 / 문체 다듬기 / 금지 표현 제거 / 협찬 표기 추가.
3. 원문에 6장 검사를 먼저 돌려 문제 목록을 보여준다.
4. 바뀌는 부분만 고친다. 원문의 말투·구조·사진 위치는 유지한다. 전체를 다시 쓰지 않는다.
5. 수정 결과를 "변경 전 → 변경 후" 표로 보여주고 확인을 받는다.
6. 정보가 바뀌었으면 본문에 "(YYYY.MM.DD 정보 업데이트)"를 적는다.
7. 반영: 글 화면의 "수정" 버튼 → 스마트에디터에서 해당 문단만 교체 → 7-1 발행 절차의 확인 단계를 거쳐 저장.

대량 수정(하루에 여러 글)은 피한다. 하루 2~3편 이하로 나눈다.

## 10. 발행

### 10-1. 발행 전 체크리스트
| # | 항목 |
|---|---|
| 1 | 6장 품질 검사 통과 (자동 7/7, 점수 85점 이상) |
| 2 | `[확인 필요]` 표시 0개 (사용자가 다 채웠나) |
| 3 | 협찬·광고 표기 (해당 시 글 맨 앞) |
| 4 | 외부 링크 0개 |
| 5 | 사진 전부 준비, 대표 이미지 지정 |
| 6 | 카테고리 선택 |
| 7 | 태그 10개 |
| 8 | 맞춤법 검사 (스마트에디터 맞춤법 기능) |
| 9 | 모바일 미리보기 확인 |
| 10 | 공개 범위 (전체공개 / 이웃공개 / 비공개) |

### 10-2. 스마트에디터 ONE 발행 절차 (브라우저 도구가 있을 때)
1. `https://blog.naver.com/<아이디>/postwrite`로 이동한다. 또는 블로그 상단 "글쓰기"를 누른다.
2. "작성 중인 글이 있습니다" 팝업이 뜨면 사용자에게 이어쓸지 새로 쓸지 묻는다.
3. 제목 칸에 제목을 입력한다.
4. 본문은 위에서부터 섹션 순서대로 넣는다. 소제목은 에디터의 "소제목" 서식을 쓴다.
5. 표는 에디터의 표 기능으로 만든다(붙여넣은 HTML 표는 깨질 수 있다).
6. 사진은 `[사진: ...]` 마커 위치에 사진 버튼으로 업로드하고, 마커 텍스트는 지운다. 파일 업로드 권한이 없으면 사용자에게 해당 위치에 직접 올려 달라고 한다.
7. 오른쪽 위 "발행" 버튼을 누르면 발행 설정 창이 열린다. 여기서 카테고리, 태그, 공개 범위, 대표 이미지, 발행 시간(즉시/예약)을 정한다.
8. **최종 "발행" 클릭 전에 반드시 멈춘다.** 사용자에게 제목, 카테고리, 태그, 공개 범위, 발행 시간을 요약해서 보여주고 명시적인 확인을 받는다. 확인 없이 발행하지 않는다.
9. 사용자가 "임시저장만"을 원하면 "저장" 버튼만 누른다.
10. 발행 후 글 URL을 열어 PC와 모바일 화면을 확인하고 URL을 사용자에게 준다.

에디터 화면 구조는 바뀔 수 있다. 버튼을 못 찾거나 2~3번 실패하면 멈추고 사용자에게 수동 진행을 안내한다.

### 10-3. 브라우저 도구가 없을 때
`post.md`, 제목, 태그, 사진 위치 안내, 10-1 체크리스트를 주고, 10-2 절차를 사용자가 직접 따라 하도록 안내한다.

### 10-4. 발행 운영 규칙
- 하루 2편 이하로 발행한다.
- 발행 시간은 매일 같은 시각으로 고정하지 않는다.
- 같은 템플릿·같은 도입부를 연속 사용하지 않는다. 최근 글의 패턴·도입부와 다른 조합을 고른다.
- 발행 직후 대량 수정·삭제·재발행을 하지 않는다.
- 사람 검수 없는 자동 연속 발행은 하지 않는다.
